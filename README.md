# 영상 자동 편집

영상 1개를 올리고 따라 하고 싶은 레퍼런스를 고르면, 컷·자막·제목 카드·구도를 레퍼런스처럼 맞춰 자동으로 편집하고, 자막 오타·화질·오디오까지 검수한 결과를 돌려줍니다. 내 컴퓨터(맥·윈도우·리눅스)에서만 도는 웹앱이에요(로그인 없음). 설계: `docs/superpowers/specs/`, 계획: `docs/superpowers/plans/`.

## 처음 시작하기

이 앱은 웹사이트가 아니라 **내 컴퓨터에서 직접 돌리는 프로그램**이에요(맥·윈도우 10/11·리눅스). 영상은 내 컴퓨터 밖으로 나가지 않고, 레퍼런스 검색과 AI 호출에만 인터넷을 써요.

**필요한 것:** Node.js 22 이상, ffmpeg, whisper-cli(음성 인식), hyperframes(렌더링), yt-dlp(레퍼런스 검색), 그리고 **[Claude Code](https://claude.com/claude-code) 설치와 로그인** — AI가 필요한 단계마다 `claude` 명령을 쓰고, **사용량은 로그인한 본인 계정에서 나가요**. 영상 한 편에 AI 호출이 여러 번 들어가요. 메모리 8GB 이상을 권해요.

**맥** (터미널)

```bash
brew install ffmpeg whisper-cpp node uv
npm i -g hyperframes
uv tool install yt-dlp
```

**윈도우** (PowerShell) — Claude Code 는 Git for Windows 가 있어야 해요

```powershell
winget install OpenJS.NodeJS Gyan.FFmpeg yt-dlp.yt-dlp Git.Git
npm i -g hyperframes
irm https://claude.ai/install.ps1 | iex     # Claude Code 설치 (설치 뒤 새 PowerShell 에서 claude 를 한 번 실행해 로그인)
```

whisper-cli 는 설치 프로그램이 없어요. [whisper.cpp 릴리스](https://github.com/ggml-org/whisper.cpp/releases)에서 **이름이 b 로 시작하는 릴리스**(예: `b5454`)의 `whisper-bin-x64.zip` 을 받아 풀고, `whisper-cli.exe` 가 든 폴더를 PATH 에 추가하세요(윈도우 설정 → 환경 변수). winget 으로 설치한 도구는 **새 PowerShell 창**을 열어야 보여요.

**리눅스** (터미널)

```bash
sudo apt install ffmpeg
npm i -g hyperframes
uv tool install yt-dlp     # uv 와 Node.js 22 이상은 각자 설치
```

whisper-cli 는 위 릴리스 페이지의 `whisper-bin-ubuntu-x64.tar.gz` 를 풀어 `whisper-cli` 를 PATH 에 두거나 직접 빌드하세요.

**공통** — 도구를 다 깔았으면:

```bash
git clone https://github.com/kuventus14/ai-video-clip.git
cd ai-video-clip
npm install
npm run setup     # 빠진 게 있으면 이 컴퓨터에 맞는 설치 방법을 알려 줘요(음성 인식 모델을 받는 명령도 나와요)
npm run app       # 그다음 http://127.0.0.1:4848
```

- **배경음악·효과음 파일은 저작권 때문에 들어 있지 않아요.** 음악 없이도 그대로 쓸 수 있고, 넣는 법은 `assets/sound/README.md` 에 있어요.
- 소리를 또렷하게 하는 기능은 선택 설치예요(아래 "목소리 보정 설치").
- **어디까지 확인했나:** 맥·윈도우·리눅스의 자동 시험(GitHub Actions)이 매번 돌아요 — 실제 ffmpeg, hyperframes 의 `check` 와 draft 렌더, 실제 `whisper-cli`(작은 모델) 호출, **앱 전체 켜기**(빌드 → 화면 서버 → 처리 프로그램 → 영상 올리기 → ffprobe 확인 → 끄기)까지 세 컴퓨터에서 통과해요. 개발자가 손으로 써 본 건 맥뿐이에요. **윈도우·리눅스에서 아직 직접 확인하지 못한 것:** 진짜 Claude Code 로 AI 를 부르는 단계, yt-dlp 로 비슷한 영상 찾기, 목소리 보정(`deep-filter`), 큰 음성 인식 모델로 긴 영상 처리. 막히면 `npm run setup` 의 안내와 진행 기록을 알려 주세요.
- 영상 올리기 → 분석 → 자막·레퍼런스 → 승인 → 제작 → 확정 순서는 아래 "화면 사용 순서"에 있어요. 라이선스는 MIT 예요(`LICENSE`).

## 실행 (한 줄)

```bash
npm run app
```

브라우저에서 **http://127.0.0.1:4848** 을 여세요. 화면(웹 서버)과 처리 프로그램(워커)이 함께 켜지고, 로그 앞에 `[web]` / `[worker]` 가 붙어요. 끄려면 `Ctrl+C` — 처리 중인 작업이 있으면 끝날 때까지 기다리고, 한 번 더 누르면 바로 꺼져요(그 작업은 다음에 "중단됐어요"로 보여요). 처음 켜거나 소스가 바뀐 뒤에는 화면을 한 번 빌드해요(1~2분). 개발할 때는 `npm run app:dev`. **윈도우에서는** 신호로 "끝까지 기다렸다 끄기"를 할 수 없어서 `Ctrl+C` 한 번에 바로 꺼지고, 처리 중이던 작업은 다음에 켤 때 "중단됐어요"로 표시돼요(다시 시도하면 돼요). 다른 포트로 켜려면 맥·리눅스는 `VAE_PORT=4949 npm run app`, 윈도우 PowerShell 은 `$env:VAE_PORT=4949; npm run app`.

## 화면 사용 순서

1. **새 영상** — 영상을 끌어다 놓거나 고르세요(mp4·mov·m4v·webm·mkv·avi, 1초~10분). 올리는 중에도 설명(선택)을 쓰고 **용도**를 고를 수 있어요. 용도는 올린 영상을 보고 자동 인식하지만, 직접 고른 값이 항상 우선이에요. 레퍼런스가 있다면 링크나 파일로 넣어도 돼요. → **분석 시작**
2. **분석** — 음성 인식, 영상 내용 파악, 비슷한 인기 영상 찾기. 1분짜리 영상 기준 30~40초.
3. **자막 편집과 레퍼런스 고르기** — 먼저 음성 인식이 받아 적은 **자막을 줄마다** 보고 틀린 곳을 고치고 빠진 곳에 줄을 더해요("자막 편집" 참고, 고치지 않고 계속해도 돼요. 레퍼런스를 미리 넣었어도 여기서 한 번 멈춰요). 레퍼런스는 추천 카드, 링크, 파일 중 하나(없이도 가능). 추천은 영상의 장르(예: "골프 레슨")로 유튜브에서 **최근 1년 안의 조회수 높은 영상**을 찾아 보여 줘요(릴스용은 4분 미만, 게시물용은 4~20분). 편집을 참고하는 용도라 주제를 좁히지 않고 넓게 찾아요. 인스타 릴스는 검색할 방법이 없어서 유튜브만 보여 줘요. 레퍼런스에서 어떤 부분을 참고할지 자연어로 적을 수 있어요. → 계속
4. **"이렇게 이해했어요"** — AI가 이해한 편집 계획을 보고 승인하세요. 이번 버전에서 지원하지 않는 항목은 노란 줄로 알려 줘요. 용도·자막(영상에 이미 자막이 있으면 끄세요)·**자막 위치**(상단·중앙·하단, 기본은 레퍼런스를 따르고 없으면 하단)·**소리**(원본 그대로 / 목소리 또렷하게)·화질을 바꾸거나 요청을 고쳐 계획을 다시 만들 수 있어요. 목소리 또렷하게는 아래 "목소리 보정 설치"를 먼저 해 두세요. AI 가 짠 **편집 구성**(훅·제목·소제목·속도)도 여기서 보고 제목·훅 질문·소개 줄은 고칠 수 있어요("편집 감독" 참고). **배경음악**(곡 고르기)과 **효과음**(켜기/끄기)도 여기서 골라요("배경음악·효과음" 참고).
5. **제작** — 1분짜리 영상 기준 2분쯤. 화면을 닫아도 계속돼요(기록에서 다시 열기).
6. **결과 확인** — 영상을 보고 검수 리포트를 확인하세요. 리포트에는 검수가 확인하지 **않은** 항목도 적혀 있어요. **확정**하면 기록에 저장돼요. 고치고 싶으면 **수정 요청**, 반대 용도(가로↔세로)가 필요하면 **다른 버전도 만들기**(분석과 레퍼런스는 다시 하지 않아요).

유튜브·인스타그램·네이버 클립 업로드는 다음 단계에서 붙어요. 지금은 결과 영상을 내려받아 올려 주세요.

## 목소리 보정 설치 (선택)

계획 승인 화면의 **소리 → 목소리 또렷하게**는 AI 소음 제거 도구 [DeepFilterNet](https://github.com/Rikorose/DeepFilterNet)의 `deep-filter`(실행 파일 1개, 약 27MB)를 써요. 설치하지 않으면 "원본 그대로"만 쓸 수 있고, 목소리 또렷하게를 고르면 설치하라고 알려 줘요.

**맥(애플 칩)** — 터미널

```bash
mkdir -p ~/.local/share/deep-filter && cd ~/.local/share/deep-filter
gh release download v0.5.6 -R Rikorose/DeepFilterNet -p 'deep-filter-0.5.6-aarch64-apple-darwin' -O deep-filter
echo "4601e7f4e4c03e59a4c5b5000216ef3add3e808799cfccd95e14e83ea4611081  deep-filter" | shasum -a 256 -c -
chmod +x deep-filter
```

**윈도우** — PowerShell (`gh` 는 `winget install GitHub.cli`, 또는 [릴리스 페이지](https://github.com/Rikorose/DeepFilterNet/releases/tag/v0.5.6)에서 `deep-filter-0.5.6-x86_64-pc-windows-msvc.exe` 를 받아 아래 위치에 `deep-filter.exe` 로 저장)

```powershell
New-Item -ItemType Directory -Force "$HOME\.local\share\deep-filter" | Out-Null; cd "$HOME\.local\share\deep-filter"
gh release download v0.5.6 -R Rikorose/DeepFilterNet -p "deep-filter-0.5.6-x86_64-pc-windows-msvc.exe" -O deep-filter.exe
(Get-FileHash -Algorithm SHA256 deep-filter.exe).Hash   # 75E11FA16445F560CB6B021521DDB89E89270D13B83089705D98776F58FD7915 와 같아야 해요
```

**리눅스(x86_64)** — 터미널

```bash
mkdir -p ~/.local/share/deep-filter && cd ~/.local/share/deep-filter
gh release download v0.5.6 -R Rikorose/DeepFilterNet -p 'deep-filter-0.5.6-x86_64-unknown-linux-musl' -O deep-filter
echo "70775e251eee44c0f2451a1e833326cf8bcbbe304d3e7cd12851e6fce72ef7da  deep-filter" | sha256sum -c -
chmod +x deep-filter
```

해시 검사 결과가 맞아야 해요(받은 파일이 이 README 를 쓸 때 확인한 파일과 같다는 뜻이에요). 다른 위치에 두려면 `VAE_DEEP_FILTER=/경로/deep-filter` (윈도우는 `deep-filter.exe` 경로) 환경변수를 써요. 인텔 맥이나 ARM 리눅스는 릴리스 페이지에서 맞는 파일을 받고 해시는 직접 확인하세요. 윈도우·리눅스에서의 목소리 보정은 아직 직접 돌려 보지 못했어요.

- 소리 처리는 영상 화면을 다시 인코딩하지 않고 **소리만** 바꿔요: AI 소음 제거 → 말소리 대역 정리 → 소리 크기를 -16 LUFS 로 맞춤. 20초 영상 소리를 몇 초에 처리해요.
- macOS 에서는 인터넷을 막은 채(`sandbox-exec`) 실행해요(윈도우·리눅스에는 같은 장치가 없어 막지 않고 실행해요). 이 도구는 소리 파일 하나를 처리하는 데 인터넷이 필요 없어요.
- **한계:** 소음은 줄고 크기는 맞지만, **방의 울림은 많이 줄지 않아요.** 마이크를 입 가까이 두지 않고 찍은 영상은 스튜디오 녹음처럼 되지 않아요. 울림 제거 AI 는 나중에 붙일 수 있게 이 단계를 따로 뒀어요. 영상 하나(소음 있는 야외 레슨)로만 강도를 정했어요.


## 배경음악·효과음

계획 승인 화면의 **배경음악**(곡 하나 또는 없음)과 **효과음**(켜기/끄기)을 고르면, 렌더가 끝난 영상에 소리를 입혀요(고르지 않으면 넣지 않아요).

- **배경음악:** 곡을 분위기(잔잔한·밝은·신나는)별로 묶어 보여 주고, ▶ 로 미리 들어 볼 수 있어요. 음악은 목소리보다 약 14 LU 작게 깔리고, **말할 때는 자동으로 6~8dB 더 줄어요**(쉬는 구간에서 다시 올라와요). 영상보다 짧은 곡은 반복하고 끝은 페이드해요.
- **효과음:** 제목 카드가 나올 때 짧은 `pop`, 컷이 바뀌는 곳마다 `whoosh` 를 넣어요. 너무 잦지 않게 2초 이상 띄워요. 넣을 곳이 하나도 없으면(컷이 없는 영상 등) 검수 리포트에 그렇게 알려 줘요.
- **크기는 AI 가 정하고, 결과 화면에서 직접 바꿀 수 있어요.** 제작할 때 AI 가 영상 장르·말하는 비율·음악 분위기를 보고 기본 규칙에서 음악·효과음을 얼마나 키우거나 줄일지(−6~+4dB) 정해요. AI 는 소리를 직접 듣지 못해서 어디까지나 추천이에요. 결과 화면의 **음악·효과음 크기** 카드에서 슬라이더(−12~+6dB)로 바꾸고 **적용**하면, 영상은 다시 그리지 않고 **소리만 다시 섞어요**(20초 영상 기준 1초 안팎). **AI 추천으로 되돌리기**도 있어요. 다시 섞기에 필요한 파일(`dry.mp4`·`mix.json`)을 제작할 때 결과 폴더에 같이 남기므로 **이 기능이 생기기 전에 만든 작업은 다시 섞을 수 없어요**(새로 만들면 돼요). 다시 섞다가 실패해도 기존 결과는 그대로 남아요.
- 레퍼런스의 음악은 쓰지 않아요. 계획 카드의 "음악" 줄은 레퍼런스에 음악이 있어 보이는지만 알려 주고, 곡은 직접 골라요.
- 명령줄: `--bgm <곡 id|none>`, `--sfx on|off`, `--audio original|voice` (곡 id 는 `npm run sound:measure` 가 만드는 `assets/sound/CREDITS.md` 에 있어요).

### 음원

음원 파일은 **저작권 때문에 이 저장소에 없어요.** 넣는 법(파일을 두고 → `sources.json` 에 적고 → `npm run sound:measure`)과 형식은 `assets/sound/README.md` 와 `assets/sound/sources.example.json` 에 있어요. 라이선스는 `CC0`, `Pixabay License`, `Mixkit Free License` 만 받아요(저작자 표시가 필요한 라이선스는 일부러 막았어요). 곡마다 출처·라이선스는 `sources.json` 에 적고, 앱 안에서 영상에 입히는 용도로만 쓰세요. 다른 폴더를 쓰려면 `VAE_SOUND_DIR=/경로`.

**한계:** 음악·효과음 크기는 영상 한 편(20초)으로 측정해서 맞췄어요. 소리가 영상 분위기와 어울리는지는 사람이 들어서 판단해야 해요(검수의 "확인하지 않은 항목"에 적혀 있어요). 무료 음원도 유튜브·인스타의 저작권 자동 감지에 걸릴 수 있다는 주장이 있는데 확인하지 못했어요 — 처음 올릴 때 비공개로 올려서 확인하세요.

## 편집 감독

레퍼런스를 따라 컷과 자막만 넣던 방식에서 한 단계 더 나아가, 계획을 만들 때 AI 가 영상(과 레퍼런스의 장면 사진)을 보고 **편집 구성**을 먼저 짜요. 호출은 한 번이고 약 15초 걸려요.

- **하는 일:** ① **훅 앞당기기** — 영상에서 눈길을 끄는 1.5~4초를 맨 앞에 한 번 더 두고 질문 문구를 띄워요 ② 화면 위에 고정되는 **제목 박스**(흰 상자) ③ **소개 줄**(최대 3줄, 색을 달리해서) ④ **소제목**(최대 5개)과 중간 **질문**(분홍, 최대 3개)·**리액션**(노란 상자, 최대 2개) ⑤ 핵심 단어를 **강조색**(레퍼런스에 있으면 그 색, 없으면 노랑)으로 바꾸고 팝업으로 띄우기 ⑥ **속도 올리기**(보통 1.1배, 최대 1.25배) ⑦ 군더더기 구간 덜어내기(최대 25%). 10초 이하 영상은 제목만 넣어요.
- **승인 전 문구 수정:** "이렇게 이해했어요" 화면의 **편집 구성** 카드에서 제목·훅 질문·소개 줄을 고칠 수 있어요(글자 수 한도가 있고 주소는 안 돼요. 한도를 넘으면 승인 버튼이 막혀요). 소제목·질문·리액션 문구는 여기서 못 고쳐요 — 마음에 안 들면 요청을 고쳐 계획을 다시 만드세요.
- **AI 가 실패하면:** 응답이 없거나 형식이 깨지면 편집 구성 없이 지금까지처럼 컷+자막(+제목 카드)으로 만들고, 계획 카드에 노란 줄로 알려 줘요. 이때도 제작은 멈추지 않아요.
- **검은 띠 자동 제거:** 가로 영상 위아래(또는 양옆)에 검은 띠가 있으면 화면 부분만 잘라서 써요. 20·40·60·80% 지점의 띠 모양이 서로 비슷할 때만 하고(어두운 장면을 띠로 오인하지 않게), 면적이 6% 미만이거나 결과가 원본의 40% 미만이면 건드리지 않아요. 찾거나 자르다 실패하면 원본 그대로 진행해요.
- **자막 색:** 레퍼런스의 자막 글자색이 너무 어두우면(영상 위 검은 테두리에 묻혀 안 보여서) 흰색으로, 강조색이 어두우면 노란색으로 바꿔요. 계획 카드에는 실제로 쓰는 색이 적혀요.

**한계:**
- **문구는 AI 가 쓰므로 사실 확인은 사람이 해야 해요.** 검수 리포트의 "확인하지 않은 항목"에 적혀 있어요(영상에 없는 말을 쓸 수 있어요).
- **원본 영상에 박힌 자막은 읽지 않아요.** 자막은 항상 음성 인식으로 만들어요. 소음이 많거나 울리는 소리는 인식이 틀릴 수 있어요(검수가 신뢰도 낮은 단어를 알려 줘요).
- **검은 띠 안에 글자·로고가 박힌 영상은 띠를 못 찾아요**(글자도 "내용"으로 보여서). 그대로 진행하고 띠도 남아요.
- 계획을 다시 만들 때마다(용도 바꾸기·요청 고치기·자막·레퍼런스 바꾸기) AI 호출이 한 번 더 늘어요.
- 훅 장면은 영상 맨 앞 4초 안이면 앞에 또 붙이지 않고(같은 말이 연달아 두 번 나오지 않게) 질문만 첫머리 위에 띄워요. 같은 종류의 중간 질문·리액션은 겹치지 않게 앞의 것이 끝난 뒤로 밀려요.
- 한 영상(20초 세로)과 레퍼런스 하나로만 구성 방식을 다듬었어요. 다른 장르·길이에서는 문구 품질이 달라질 수 있어요.

## 화면 구성: 자르지 않고 가운데 + 블러 띠

원본 비율이 만들 화면(릴스·숏츠용 세로 9:16, 게시물용 가로 16:9)과 다르면 영상을 **자르지 않고 가운데에 두고**, 남는 곳을 같은 장면을 흐리게(그리고 조금 어둡게) 채워요. 가로 → 세로는 위아래, 세로 → 가로는 양옆이에요. 계획 카드의 "화면 구성" 줄이 어느 쪽인지 알려 줘요.

- **글자는 띠에 놓여요.** 16:9 가로 → 세로는 제목 박스·소개 줄·소제목·질문이 **위 띠**에, 자막이 **아래 띠**에 들어가요(자막 위치를 "상단"으로 고르면 위 띠 안의 제목 묶음 아래에).
- **1:1·4:5 원본**은 띠가 얕아서 제목 묶음은 위쪽에 놓이고(4:5는 영상 맨 위에 조금 걸칠 수 있어요), 자막은 띠가 아니라 화면 아래에서 약 17% 위에 놓여요(영상 아래쪽에 얹혀요 — 인스타·유튜브의 계정명·설명 UI 밑으로 내려가거나 잘리지 않게). "상단" 자막은 영상 위쪽이에요. **3:4에 가까운 영상**과 **21:9 → 16:9** 도 띠가 모자라 글자가 영상 위쪽에 얹혀요.
- **한계:** 16:9 영상은 세로 화면 높이의 약 1/3만 차지해서 영상이 작게 보여요(자르지 않으므로). 영상 두 개(배경 + 앞)를 겹쳐 렌더해서 세로 영상 그대로 만들 때보다 느려요 — 20초 가로 샘플 기준 렌더 약 63초(세로 영상은 약 45초)이고, 컴퓨터가 바쁠 때나 검수 재작업이 돌면 훨씬 더 걸려요.
- 사람을 따라 자르는 기능(인물 인식·크롭)은 코드에 남아 있지만 앱은 더는 고르지 않아요.

## 자막 편집

음성 인식(whisper)은 100% 정확하지 않아서(특히 소리가 울리거나 먹먹할 때), 분석이 끝나면 **영상의 모든 자막을 보여 주고 사용자가 고치게** 해요. 편집 감독이 문구를 쓰기 **전에** 고치므로 AI도 고친 글자를 보고 제목·질문을 써요. 고치지 않고 계속해도 돼요.

- **할 수 있는 것:** 인식한 줄의 **글자**·**시작/끝 시각** 고치기, 줄 **나누기**(글자 사이에 커서를 두고 누르면 시간을 글자 수 비율로 나눠요)·**합치기**(다음 줄과)·**지우기**, 인식이 놓친 구간에 **새 줄 추가**, **원래대로**(인식한 그대로로 되돌리기). 줄마다 시각 버튼을 누르면 그 구간만 재생해서 들어 볼 수 있어요. 인식기가 확신하지 못한 **의심 단어**와 고친 줄의 원문이 표시돼요.
- **말이 없는 영상(음악만 있거나 소리가 없는 영상)도** 같은 편집기가 나와요. 영상 전체가 "자막이 없는 구간"으로 보이고, 줄을 추가해 직접 자막을 넣을 수 있어요(안 넣어도 돼요). 이런 영상은 자막을 넣어도 컷은 아무것도 자르지 않아요.
- **인식이 놓친 구간:** 줄 사이가 1초 넘게 비면 "자막이 없는 구간 17.0~20.1초 — 이 구간에 자막 추가"가 나와요. 영상을 보다가 "영상 현재 위치에 줄 추가"를 눌러도 돼요. 시각은 이웃한 줄과 겹치지 않게(줄 하나는 0.2초 이상) 알아서 맞춰져요.
- **줄이 많을 때:** 줄이 40개를 넘으면 "고치기 좋은 줄만 보기"가 처음부터 켜져요(의심 단어가 있는 줄과 고치거나 새로 넣은 줄만 보여요. 자막 없는 구간은 이 보기에서 숨겨요). 끄면 전부 보여요.
- **들어가는 길 3곳:** ① 분석이 끝난 뒤 레퍼런스 고르는 화면 ② 계획 확인 화면의 "자막·레퍼런스 바꾸기" ③ 결과 화면의 "자막 고치기"(확정하기 전까지). ②·③에서 "계속"하면 고친 자막으로 계획부터 다시 만들어요(AI 호출이 한 번 더 늘어요).
- **고친 자막은:** 편집 구성(AI가 고친 글자를 보고 씀), 최종 자막에 그대로 쓰여요. 검수의 자막 교정(AI)이 고친 줄을 다시 바꾸지 않고, "신뢰도 낮음" 경고도 고친 줄에는 안 떠요. 저장은 줄 목록 전체(자막 트랙)로 해요.
- **자막을 바꿔도 영상 컷은 그대로예요:** 컷은 원래 인식 결과로 계산해요(줄을 지워도 그 조용한 구간이 잘려 나가지 않아요). 인식이 놓친 구간에 줄을 추가하거나, 줄의 시작·끝을 인식된 말 바깥으로 0.3초 이상 늘리면 그 구간은 컷에서 지켜지고 자막도 그 시간에 떠요(그보다 조금 늘린 건 말한 구간 그대로예요).
- **"다른 버전도 만들기"** 는 고친 자막을 이어받아요. 분석을 다시 하면(실패 후 재시도) 새 인식 결과 기준이라 고친 자막은 비워져요.

**한계:**
- 줄 안의 **단어별 시각은 근사**예요. 고친 글자를 그 줄의 시간 안에 글자 수 비율로 나눠 넣어서, 줄 전체 타이밍은 정확하지만 강조 단어 팝업이 아주 조금 어긋날 수 있어요.
- **화면의 줄이 영상에 뜨는 자막 조각과 1:1은 아니에요.** 영상의 자막은 한 번에 14자·2.5초 안에서 다시 묶이기 때문에 한 줄이 여러 조각으로 나뉘거나, 줄 경계를 넘어 한 조각으로 묶일 수 있어요(말하는 순서와 글자는 그대로예요). 처음 줄 나누기는 글자 18자 안팎·0.7초 넘는 쉼·문장부호 기준이고, 나누기·합치기로 바꿀 수 있어요.
- **고친 글자가 맞는지는 사용자가 책임져요.** AI가 확인하지 않아요(검수의 "확인하지 않은 항목"에 문구 확인이 이미 적혀 있어요).
- 10분짜리 영상은 줄이 200개 안팎이에요. 정확도 자체(큰 whisper 모델·목소리 보정 소리로 인식)는 아직 그대로예요.

## 데이터

## 한계 (실측: 맥 8GB)

| 입력 | 분석 | 제작(렌더+검수) | 최대 메모리 | 임시 디스크 |
|---|---|---|---|---|
| 세로 57초(실제 샘플), 세로 결과 | 약 30초 | 100초 | 약 0.8GB | — |
| 세로 57초 → 가로(블러 배경) | 계획 4초 | 120초 | 약 1GB | — |
| **세로 10분 → 가로(블러 배경)**, 무음 구간 60곳 컷 → 결과 4분 8초 | 21초 | **570초(약 9.5분)** | **약 0.9GB**(워커와 렌더 프로세스 합) | **최대 약 3GB**(렌더 중), 작업 폴더 427MB |

- 제작 시간은 결과 길이의 2~3배쯤이에요(10분 영상을 무음 컷 없이 그대로 만들면 그만큼 더 걸려요). 작업은 **한 번에 하나**씩 처리하고 나머지는 순서를 기다려요.
- 입력은 1초~10분. 하단 자막바, 카메라 워크·실사 합성 VFX 는 이번 버전에 없어요. 용도마다 결과는 하나예요.
- 편집 감독을 켠 20초 세로 영상(실제 샘플): 편집 구성 약 15초, 승인 뒤 제작 약 80초(렌더 45초 + 속도 조정 14초 + 검수 8초). 같은 20초를 **가로**로 올려 세로로 만들면(가운데 + 블러 띠) 제작 약 110초(렌더 63초 + 속도 조정 22초 + 검수 18초). 결과는 1.1배속이라도 앞에 훅 3초가 붙어 원본보다 길 수 있어요.
- 음성이 많은 10분 영상의 분석 시간은 아직 재지 못했어요(위 10분 영상은 소리만 있고 말이 없어서 분석이 빨리 끝났어요).
- 제작 중에는 다른 무거운 앱(영상 편집기·브라우저 탭 여러 개)을 닫아 두세요.

## 문제가 생기면

- **"이미 다른 프로그램이 포트를 쓰고 있어요"** — 앱이 이미 켜져 있는지 보거나 `VAE_PORT` 로 다른 포트를 쓰세요.
- **"순서를 기다리는 중이에요"가 계속돼요** — 처리 프로그램이 꺼져 있는 거예요. `npm run app` 으로 켰는지 확인하세요(워커가 죽으면 3초 뒤 자동으로 다시 켜져요).
- **"작업이 중간에 멈췄어요"** — 앱이 꺼졌거나 맥이 잠들었어요. **다시 시도**를 누르면 멈춘 단계부터 이어서 해요.
- **추천이 비어 있어요** — 인터넷이 안 되거나 `yt-dlp` 가 오래됐을 수 있어요(`uv tool upgrade yt-dlp`). 링크나 파일로 직접 고르거나 레퍼런스 없이 계속할 수 있어요.
- **레퍼런스 링크가 안 받아져요** — 비공개이거나 로그인이 필요한 영상이에요(인스타그램 등). 영상을 mp4 로 받아 파일로 올려 주세요.
- **렌더가 실패해요** — 메모리가 부족할 수 있어요. 다른 앱을 닫고 `hyperframes doctor` 로 점검하세요.
- **`claude` 오류** — 터미널에서 `claude` 를 한 번 실행해 로그인돼 있는지 확인하세요.

## 필요한 도구

맨 위 "처음 시작하기"의 명령으로 설치하고, `npm run setup` 으로 점검해요(빠진 것은 설치 방법을 알려 줘요). 음성 인식 모델(`~/.cache/hyperframes/whisper/models/ggml-small.bin`, 약 465MB)은 `npm run setup` 이 보여 주는 `curl` 명령으로 받아요.

## 명령줄로 쓰기 (화면 없이)

```bash
npm run edit -- --video ~/Desktop/내영상.mp4 --out data/결과 \
  --reference "https://www.youtube.com/shorts/xxxx" \
  --description "골프 레슨 영상입니다" \
  --request "자막 스타일만 따라 하고 컷은 더 빠르게"
```

| 옵션 | 뜻 |
|---|---|
| `--video` `--out` | 필수. 결과 폴더에 `result.mp4`, `report.json` 이 생겨요 |
| `--reference` | 레퍼런스 mp4 경로 또는 유튜브·인스타 링크 (없으면 기본 스타일) |
| `--description` | 영상 설명 (없으면 AI가 영상을 보고 판단) |
| `--purpose auto\|post\|short` | 게시물용(가로) / 릴스·숏츠용(세로). 기본 `auto`, 직접 고르면 그 값이 우선 |
| `--request` | 레퍼런스에서 참고할 부분 (없으면 AI가 알아서) |
| `--quality draft\|looks\|delivery` | 렌더 화질. 기본 `looks` |
| `--captions auto\|off` | 자막. 영상에 이미 자막이 구워져 있으면 `off` |
| `--audio original\|voice` | 소리. `voice` 는 소음을 줄이고 목소리 크기를 맞춰요(목소리 보정 도구 필요) |
| `--bgm <곡 id\|none>` | 배경음악. 기본 `none` |
| `--sfx on\|off` | 효과음. 기본 `off` |

## 시험

```bash
npx vitest run                  # 기본 (합성 영상 + 가짜 claude)
INTEGRATION=1 npx vitest run    # 실제 샘플 영상·유튜브 내려받기까지 (샘플: ~/Desktop/롱아이언_릴스_편집본.mp4)
npm run seed:demo               # 모든 상태의 시연 작업을 data-demo/ 에 만든다 (화면 확인용)
VAE_DATA_DIR=data-demo npm run web:dev   # 시연 데이터로 화면만 켜기 (워커 없음)
```

## 구조

- `src/core/` 편집 엔진 — `media` 영상 정보·H.264 변환 · `transcribe` whisper · `purpose` 용도 인식 · `understand` 영상 이해 · `reference` 레퍼런스 받기 · `search` 추천 · `styleSpec` 레퍼런스 분석 · `interpret` 요청 해석 · `person`+`reframe` 인물 추적·크롭 · `cuts` 컷 계획 · `timeline` 컷 이후 시간 변환·자막 큐 · `compose` hyperframes 프로젝트·렌더 · `qaChecks`+`qa` 검수 · `pipeline` 분석→계획→제작 · `llm` `claude -p` 호출.
- `src/worker/` 처리 프로그램(작업을 하나씩 집어 단계별로 실행) · `src/db/` SQLite 작업 저장소와 상태 기계 · `src/web/`+`app/api/` API · `app/`+`components/`+`src/ui/` 화면 · `src/shared/` 화면·서버가 같이 쓰는 타입.
- 화면과 서버 쪽 코드는 `src/core`·`src/worker` 를 직접 불러오지 않아요(`tests/boundary.test.ts` 가 지켜요).
- 화면 디자인 노트: `docs/superpowers/plans/2026-10-20-02-design-notes.md`, 제품 맥락: `PRODUCT.md`.
