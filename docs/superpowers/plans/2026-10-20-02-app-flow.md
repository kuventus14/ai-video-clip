# 영상 자동 편집 — 앱·화면·흐름 구현 계획 (Plan 2/3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 1 의 편집 엔진을 브라우저에서 쓴다. 영상 업로드 → 분석 → 레퍼런스 선택(추천 또는 직접 입력) → "이렇게 이해했어요" 승인 → 제작 → 결과 확인·Confirm → History, 그리고 "다른 버전도 만들기"까지 **localhost 웹앱**으로 만든다. 업로드 버튼은 Plan 3.

**Architecture:** 한 패키지 안에 세 덩어리. ① `app/` — Next.js 16 화면과 API(요청을 받아 DB 에 적고, 파일을 스트리밍한다). ② `src/db/` — 내장 SQLite(`node:sqlite`) 작업 저장소와 상태 기계. ③ `src/worker/` — 별도 프로세스가 DB 의 대기 작업을 하나씩 집어 Plan 1 엔진(`src/core`)을 단계별로 실행한다. **`app/` 은 `src/core`·`src/worker` 를 절대 가져오지 않는다**(경계 시험으로 강제) — 엔진은 `import.meta.dirname` 등 번들러에 맞지 않는 코드를 쓰고, 화면 서버가 무거운 일을 직접 하면 안 되기 때문. 엔진의 한 번에 끝나는 `runEdit` 은 화면의 대화형 흐름에 맞게 `analyzeInput` → `prepareEdit` → `produceEdit` 세 단계로 쪼갠다(`runEdit` 은 세 단계의 합성으로 남아 CLI·기존 시험이 그대로 통과).

**Tech Stack:** Next.js 16.4.2(Turbopack, App Router), React 19.3.1, Tailwind 4.3.3(`@tailwindcss/postcss`), Node 24 `node:sqlite`, 기존 Vitest·tsx·zod. 시험 앱으로 확인한 사실: Next 16 빌드에서 `node:sqlite` 를 쓰는 라우트가 빌드·동작함 / 400MB 스트리밍 업로드 중 서버 메모리 89→171MB(통째로 올리지 않음) / Range 요청은 206, 내려받기 해시 일치. 레퍼런스 추천은 `yt-dlp` 로 키 없이 동작(아래 Task 4).

**Spec:** [`docs/superpowers/specs/2026-10-20-video-autoeditor-design.md`](../specs/2026-10-20-video-autoeditor-design.md) · 앞선 계획: [`2026-10-20-01-edit-core.md`](2026-10-20-01-edit-core.md) · 그 판단 기록: [`…-ledger.md`](2026-10-20-01-edit-core-ledger.md). 브랜치: `app-flow`(= `edit-core` 에서 분기, 로컬 전용).

## Global Constraints

- 사용자는 **본인 한 명**. 로그인·서버 배포 없음. 서버는 **`127.0.0.1` 에만 바인딩**, 기본 포트 `4848`(`VAE_PORT`). 데이터는 사용자 단위로 나눌 수 있게 작업 행에 `owner_id`(기본 `'local'`)를 둔다. (스펙 8, 11)
- 용도 `'post'`(게시물 가로) / `'short'`(릴스·숏츠 세로). **사용자가 고른 값이 자동 인식보다 항상 우선**, 자동 인식 결과는 업로드 직후 미리 선택된 채 보인다. 결과물은 선택한 용도 하나, "다른 버전도 만들기"로 반대 용도를 추가한다. (스펙 5-1, 11)
- 편집 결과·검수 리포트·"이렇게 이해했어요" 카드는 Plan 1 의 `EditResult`/`report.json` 값 그대로 화면에 보여 준다 — 화면이 값을 가공해 거짓을 말하지 않는다(미검수 항목 `unchecked`, 자동 적용하지 않은 교정 `suggestions` 포함).
- **게시는 사용자가 버튼을 눌렀을 때만**. 이 계획에는 업로드 기능이 없다(결과 화면에 Plan 3 자리만 비워 둔다).
- 사용자에게 보이는 모든 글은 한국어. 시간 표시는 한국 시간.
- API: `export const runtime = 'nodejs'`, DB 를 쓰는 라우트는 `export const dynamic = 'force-dynamic'`. 동적 세그먼트는 `ctx.params` 가 **Promise**(Next 16). 응답은 `Response.json`(NextResponse 쓰지 않음) — 라우트 파일을 시험에서 직접 불러 `new Request(...)` 로 호출할 수 있게.
- 큰 파일은 **스트리밍**으로만 다룬다(`req.body` → 파일, 파일 → `Range` 응답). `request.formData()` 로 통째로 읽지 않는다.
- 변경 요청(POST/PUT/DELETE)은 **`Origin` 이 있으면 `Host` 와 같아야** 통과(다른 사이트가 내 로컬 앱을 건드리지 못하게). `Origin` 이 없는 호출(curl)은 허용.
- 작업 id 는 `^[a-f0-9]{10}$`. 업로드 파일 이름은 쓰지 않고 확장자(`mp4 mov m4v webm mkv avi`)만 쓴다 — 경로 이탈·한글 파일명 문제 방지.
- 워커는 **한 번에 작업 하나**(8GB 맥). 일상 실행은 `next build` + `next start`(개발 서버보다 메모리를 덜 쓴다), 화면 개발 때만 `next dev`.
- **화면은 실행해서 눈으로 확인한다**(시험 통과 ≠ 보이는 것). 화면 작업 전에 `impeccable`, `ui-ux-pro-max`, `design-taste-frontend` 스킬을 불러 디자인 방향을 잡고, 끝나면 `preview_start` 로 띄워 상태별 스크린샷·콘솔 오류·너비 1280/1024/390 을 확인한다.
- Git: 로컬 커밋만(작업마다), push 없음, 메시지 끝에 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. 폴더 이동이 필요한 명령은 `cd <경로> && test "$(pwd)" = <경로>` 로 **이동을 확인한 뒤** 실행(시험 앱 실수로 프로젝트 설정이 덮어써질 뻔한 일이 있었다).
- 돈·크레딧이 드는 일은 없다(`claude -p` 는 로그인 사용, 외부 유료 API 없음).

## Review Focus

시험이 직접 두드리지 않으면 사용자가 겪을 가능성이 큰 상황(각 줄의 시험은 소유 작업에 있다).

1. **업로드가 도중에 끊기거나 취소됨** → 반쯤 쓴 파일이 남아 작업이 영영 "올리는 중"으로 보이지 않는다 (Task 6).
2. **같은 작업을 두 탭에서 동시에 조작**(승인을 두 번 누름) → 한 번만 처리되고 둘째는 409 (Task 2, 7).
3. **워커가 중간에 죽음**(맥 잠자기·강제 종료) → 재시작 시 "중단됨" 으로 표시하고 재시도할 수 있다 (Task 2, 5).
4. **레퍼런스 추천이 실패/0개/인터넷 없음** → 화면이 막히지 않고 링크·파일을 직접 넣을 수 있다 (Task 4, 5, 12).
5. **한글·공백 파일명, 수 GB 파일, 허용되지 않는 확장자** → 스트리밍으로 받고 메모리가 늘지 않으며, 이상한 확장자는 거절한다 (Task 6).
