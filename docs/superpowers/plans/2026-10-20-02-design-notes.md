# 화면 디자인 노트 (Plan 2 — "편집실")

한국어 도구형 앱, 사용자 한 명, 데스크톱 우선, **영상이 주인공**, 단계형 흐름. 제품 맥락은 `PRODUCT.md`. 이 문서는 구현이 따르는 값만 적는다.

첫 버전(청회색 바탕 + 흰 패널)이 "너무 밋밋하다"는 평가를 받아, 기능은 그대로 두고 화면 전체를 다시 디자인했다. 쓴 스킬: `design-taste-frontend`(방향·검사·비평), `frontend-design`(방향 계획), `impeccable`(첫 구현·맥락). `ui-ux-pro-max` 는 쓰지 않았다.

## 방향: 편집실

- **다크 전용**(`color-scheme: dark`). 진짜 검정 무대(`--stage`) 위에서 영상이 주인공이고, 면은 밝기 단계(`ground → surface → raised → lift`)로만 구분한다. 테두리·그림자로 높이를 말하지 않는다(그림자는 떠 있는 ActionBar·대화상자만).
- **호박색 = "지금 여기"**: 재생헤드, 진행, 고른 것, 내 차례. **흰색 알약 = "확정하는 행동"** 하나. 둘이 겹치지 않는다.
- 척추는 **타임라인 전송 막대**(`Steps`): 눈금 위를 재생헤드가 지나가고, 완료 구간은 호박색, 기다리는 중이면 헤드가 구간 안을 움직이고 내 차례면 멈춘다. 작업 줄에서는 작은 읽기 전용 버전(`compact`)으로 쓴다.
- **필름 갤러리**(홈): 확정한 영상은 높이가 같고 폭은 영상 비율대로인 카드로 한 줄에 나란히 선다(가로·세로 섞임). 마우스를 올리면 결과 영상이 소리 없이 미리 재생된다. 진행 중·실패 작업은 모니터 행.
- 영상은 항상 **원래 비율**로 검은 무대 가운데에 서고, 세로 영상 뒤에는 흐린 포스터 역광(ambient)만 깐다.

## 움직임 (사용자가 요청한 모션그래픽)

모두 `app/globals.css` 에 있고 `prefers-reduced-motion` 에서 한꺼번에 꺼진다.

- 불러오기 시퀀스 한 번: 제목 `.wipe`, 본문 `.enter`(`--i` 로 순서). 카드마다 흩뿌려 넣지 않는다.
- 진행 무대(`StageGraphic`): 단계마다 그림이 다르다 — 음성 인식 파형, 장면 스캔, 영상 확인 프로브, 스트립, 컷 계산, 렌더링 48칸 격자, 검수 체크, 대기 리더. 위에 단계 칩·경과 시간·타임코드.
- 뷰파인더 모서리(`.vf`), 드롭존 화살표 부유(`dz-float`), 확정 시 클래퍼보드 연출(`clap-*`), 재생헤드 이동.

허용한 예외(스킬의 "그라디언트·글로우 금지" 규칙을 사용자의 명시 요청에 맞춰 푼 곳): 썸네일 글자용 아래쪽 어두운 막, 재생헤드의 번짐, 포스터 역광. 그 밖의 장식 그라디언트는 없다.

## 글꼴·크기·모서리

- **Pretendard Variable**(npm `pretendard`, 필요한 글자 조각만 불러오는 dynamic-subset woff2, 로컬 서빙). 숫자는 `tabular-nums`, 한국어는 `word-break: keep-all`.
- 홈 제목 44px(표현형 제목은 요청에 따라 키움 — inspect 의 h1 경고는 이 이유로 유지), 계획 한 줄 요약 24–28px, 본문 15–16px, 보조 13px, 라벨 12px.
- 모서리: 컨트롤 12 / 패널 20 / 칩 8 / ActionBar 28 / 필름 카드 18. 터치 대상 높이 최소 40px(작은 버튼 36px).
- 본문 최대 폭 1240px, 좌우 여백 모바일 20px·데스크톱 32px. 업로드 화면은 큰 화면에서 왼쪽 무대(고정) + 오른쪽 입력 두 열.

## 화면별 요약

- **홈**: 한 줄 요약("내 차례 N개 · 만드는 중 N개 · 멈춘 작업 N개 · 확정한 영상 N개") + 모니터 행 + 필름 갤러리.
- **새 영상**: 드롭존(뷰파인더) → 올리는 동안 퍼센트·검사 그림 → 올린 영상 재생 + 용도 3타일(자동 인식 / 가로 / 세로, 실제 첫 프레임 미리보기).
- **레퍼런스**: "이런 영상으로 이해했어요" 요약 + 포스터 카드(고르면 호박색 링·"선택함"·버튼 문구가 바뀜).
- **계획 승인**: "이렇게 이해했어요" 한 줄 요약 + 항목마다 아이콘(`planItemKind`), 반영 안 되는 줄은 노란 줄.
- **결과**: 플레이어 + 타임라인(검수가 짚은 시각 점 — 눌러서 이동) + 판정·큰 타임코드 + 행동. 확정하면 클래퍼보드 배너.

## 상태 문구와 단계

`STATUS_LABEL`(src/ui/format.ts)이 상태의 한국어 문구를 한 곳에서 정한다. 단계는 업로드·분석·레퍼런스·계획 확인·제작·결과. 실패한 작업은 `failedPhase` 로 어느 단계에서 멈췄는지 눈금자에 표시한다. 화면용 순수 함수(`thumbAspect`, `stageVisual`, `phaseStages`, `currentStageIndex`, `timecode`, `ROW_CTA`, `sourceFrame`, `planItemKind`)는 모두 테스트가 있다.

## 검증 기록

- `inspect.mjs`(실제 Chrome 1440/768/390): 9개 화면 × 3폭에서 FAIL 0. 남은 WARN 은 위 h1 44px, 업로드 왼쪽 고정 열의 들쭉날쭉한 행, 모서리 반경 혼용(의도), 데모용 시험 영상의 색 번잡.
- 실제 흐름: 샘플 영상 업로드 → 분석(음성 인식·추천 12개) → 레퍼런스 고르기 → 계획 승인 → 렌더링 → 검수 통과 → 확정, 홈 카드 호버 미리보기, 검수 점 이동까지 브라우저에서 확인.
- 알려진 한계: 1280/1024 폭은 패널 크기 때문에 스크린샷 검증을 못 했다(390/768/1440 만 확인). 말이 많은 10분 영상의 분석 시간은 아직 재 보지 않았다.
