# 영상 자동 편집 — 편집 감독(구성 재편집) 구현 계획 (Plan 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 지금 앱은 군더더기 컷과 자막, 제목 카드만 넣는다. 사용자가 Claude 앱의 "릴스편집" 탭에서 영상 두 개(내 영상 + 레퍼런스)를 보여 주고 시켰을 때 나오는 수준 — **훅 장면을 맨 앞으로 옮기고, 상단 고정 제목·소제목·핑크 훅 질문·리액션 자막을 올리고, 대사 자막의 핵심 단어를 강조하고, 1.1배속으로 템포를 올리는 편집** — 을 AI "편집 감독"이 편집 대본으로 짜고 앱이 그대로 렌더하게 만든다. 승인 전에 사용자가 문구를 고칠 수 있다.

**Architecture:** 새 `director` 단계가 계획 단계(`prepareEdit`)에서 영상·대본·레퍼런스 화면을 AI 에 보여 주고 **편집 대본(`EditScript`, zod 로 검증·정리)** 을 받는다. 대본은 `prepared.json` 에 저장되어 계획 카드와 승인 화면에 보이고, 제작 단계(`produceEdit`)가 그 대본대로 (1) 타임라인(훅 장면을 앞에 붙임) (2) 화면 위 오버레이 층(제목·소개 줄·소제목·질문·리액션)과 강조 자막 (3) 렌더 뒤 속도 조정(`tempo`)을 한다. 컷 계산(`planCuts`)·리프레임·검수·소리 입히기는 그대로 쓴다. AI 가 실패하거나 엉터리를 내면 **지금 방식(컷+자막)으로 되돌아가** 작업이 멈추지 않는다.

**Tech Stack:** 기존(Node 24 + TypeScript, zod, Vitest, hyperframes, ffmpeg, `claude -p` 호출기 `src/core/llm.ts`). 새 의존성 없음.

**Spec:** [`docs/superpowers/specs/2026-10-20-video-autoeditor-design.md`](../specs/2026-10-20-video-autoeditor-design.md) (5장 편집 파이프라인, 안티골: 레퍼런스의 화면·음원을 결과에 쓰지 않는다). 이 계획은 스펙의 "영상 구성(structure) 따라 하기"를 `unsupported` 에서 `approximate` 로 올린다. 브랜치 `director`(미병합 `refs-captions` 위).

## 사용자가 가진 기준 (붙여 준 "릴스편집" 탭 대화에서 읽은 것)

입력은 "비디오 1(내 영상) + 비디오 2(레퍼런스)". 결과는 9:16, 56.8초. 그 탭이 한 일:
- **후킹:** 원본 54초쯤의 풀스윙을 맨 앞에 넣고 핑크색 큰 질문("롱아이언, 왜 나만 안 맞을까?")을 띄움 → 이어서 3줄 소개(노란 소제목 / 하늘색 한 줄 / 흰 한 줄).
- **상단:** 흰 박스 제목("프로님의 롱아이언 꿀팁")이 계속 고정, 그 아래 노란 소제목이 "여기서 포인트!" → "체크 방법!" → "적용해보면!" 순으로 바뀜.
- **중간 후킹 질문:** 핑크색("아마추어는 백스윙이 짧다?", "왼쪽 티셔츠, 찌그러지나요?"), **리액션:** 마지막 스윙에 노란 박스("와.. 롱아이언이 이렇게 뻗는다고?!").
- **대사 자막:** 하단 띠에 흰 글씨, **핵심 단어만 노란색**, 톡 튀어나오는 팝업 애니메이션.
- **템포:** 말 없는 구간 컷 + 전체 1.1배속(60.8초 → 56.8초). **화면:** 가로 영상(위아래 검은 띠)을 띠 없이 키워 가운데 두고, 위아래는 같은 장면을 흐리게 채움.
- 문구는 AI 가 정하고, 사용자가 "다르게 하고 싶으면 알려 달라"고 열어 둠.

## Global Constraints

- 편집 대본은 **zod 로 검증·정리**한 뒤에만 쓴다. 시간은 원본 길이 안으로 자르고, 문구는 한국어·글자 수 상한(제목 18, 질문·리액션 22~24, 소제목 10, 소개 줄 22)을 넘으면 뺀다(잘라 붙이지 않는다). 개수 상한: 소제목 5, 중간 질문 3, 리액션 2, 소개 줄 3, 강조 단어 30.
- 문구는 **영상에 나온 말·화면에서 근거를 둔 내용만**. 없는 수치·사실·인물을 지어내지 않는다(프롬프트 규칙 + 사용자가 승인 전에 고침).
- 레퍼런스의 **원본 영상·음원은 결과에 쓰지 않는다**(스펙). 레퍼런스에서는 스타일·구성 관찰만 쓰고, AI 에게 보여 주는 것은 뽑아 둔 장면 사진(JPEG)뿐이다. 사진은 작업 폴더(`ref-frames/`)에만 두고 작업을 지우면 같이 지운다.
- AI 호출은 `src/core/llm.ts` 한 곳(`askClaude`)을 통과한다. 새 호출은 `effort: 'medium'` 이상, 이미지 최대 28장. 감독 단계는 실패해도 작업을 막지 않는다(info 로 알리고 지금 방식으로 계속).
- 시간은 초(float), 사용자에게 보이는 문자열은 한국어. 훅 장면은 **1.5~4초**, 맨 앞에 한 번, 본편에서도 원래 자리에 다시 나온다(편집 의도).
- 경계: `app/ components/ src/shared/ src/db/ src/web/ src/ui/` 는 `src/core`·`src/worker` 를 가져오지 않고, 화면 코드는 `src/shared/sound.ts`·`voice.ts` 에서 **타입만** 가져온다. 편집 대본의 화면용 타입은 `src/shared/types.ts` 에 둔다.
- DB 마이그레이션은 이 계획이 **6번**을 쓴다(main 4번 배경음악, `refs-captions` 5번 자막 위치). `upload` 브랜치의 uploads 마이그레이션은 합칠 때 7번으로 옮긴다(장부에 적을 것).
- **UI 는 반드시 띄워서 눈으로 확인한다.** 시험 통과만으로 완료라 하지 않는다. 화면을 만든 뒤 `.next` 는 지운다.

## Review Focus

계획의 시험이 직접 확인하지 않으면 사용자가 겪을 가능성이 큰 다섯 가지 (각 줄의 시험은 소유 작업에 들어 있다).

1. **훅 장면이 본편에서도 나오는데** 자막이 두 번 달리거나 소리·크롭이 어긋남 (훅은 자막 없이 소리만, 본편은 원래대로) (Task 2, 4, 6).
2. **아주 짧은 영상(10초 이하)·말 없는 영상**에서 AI 가 훅·소제목을 억지로 만들어 영상이 더 나빠짐 → 짧으면 훅·소제목을 빼고 제목만 (Task 1, 6).
3. **AI 가 엉터리 JSON·범위 밖 시간·너무 긴 문구**를 줌 → 정리되거나 지금 방식으로 되돌아가고 작업은 멈추지 않음 (Task 1, 3, 6).
4. **긴 한국어 문구가 화면 밖으로 넘치거나 서로 겹침**(가로 영상 → 세로 블러 채우기, 자막 위치 상단 선택, 제목 카드와 소제목) (Task 4).
5. **1.1배속 뒤 자막·효과음·음악이 어긋남**(자막 시각, 총 길이 = 렌더 길이 ÷ 속도, 효과음 위치) (Task 5, 6).
